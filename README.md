# total‑factor‑operation‑system
全要素经营管理系统

钻井单井经营管控 v3.0 网页版：专业部室管“价”，基层队管“量”，程序算“钱”。界面按 [`ui/`](ui/README.md) 中的 v3.0 原型实现，表结构按《钻井单井经营管控系统 核心数据库表设计》和 [`docs/`](docs/) 中的主逻辑线建立。

## 运行

需要 Python 3.11+ 和 Node.js 20+。

```bash
pip install -r backend/requirements.txt
```

```bash
npm --prefix frontend install
```

```bash
npm --prefix frontend run build
```

```bash
python -m uvicorn --app-dir backend app.main:app --port 8000
```

打开 http://localhost:8000 。首次启动会在 `backend/data/tfos.db` 建库并写入示例数据；删除该文件即可重置。

开发时前端可单独热更新：后端照常启动，再运行 `npm --prefix frontend run dev`，打开 http://localhost:5173（`/api` 自动代理到 8000）。

测试：

```bash
cd backend && python -m pytest -q
```

## 结构

| 目录 | 内容 |
| --- | --- |
| `backend/app/schema.sql` | SQLite 表结构：主数据、依据与规则、事实（成本日报）、经济事项、计算批次；触发器保证事项只冲不改、已发布规则只增不改 |
| `backend/app/engine.py` | 规则引擎：已审核事实 × 已发布规则 → 经济事项；按 收入 → 直接成本 → 比例计提 顺序计算，变化只冲销重算；回算测试 |
| `backend/app/wellinfo.py` | 单井基础信息填报：字段与《单井基础信息表》一致；校验节点顺序与开次；自动算周期、状态、登记与完井填报滞后；提交后同步 well、team、well_milestone、team_well_period 并按需重算 |
| `backend/app/reports.py` | 成本日报：报量行由规则库生成、阻断 / 警告校验、提交、审核、驳回、更正 |
| `backend/app/rules.py` | 规则维护：草稿 → 待确认 → 回算中 → 待发布 → 已发布 → 已被替代，调价新建版本 |
| `backend/app/analysis.py` | 经营总览、单井、成本构成、经济事项、溯源、对标分析，全部从经济事项汇总 |
| `backend/app/costdetail.py` | 费用明细：每项成本科目按时间 / 市场 / 区块 / 队伍汇总并导出 Excel（每个维度一个工作表，另附逐笔“事项明细”）；金额取经济事项有效金额，与经营总览同源；部室只含归口科目、不含收入；每次导出写入审计日志 |
| `backend/app/results_import.py` | 单井经营结果按《单井经营情况导出模板》导入，列转行写入“历史导入”经济事项 |
| `backend/app/excel.py` | 按《单井经营情况导出模板》导出；成本日报 Excel 模板导出与导入（导入只存草稿） |
| `backend/app/auth.py` | 四个角色的菜单、功能权限与行级数据权限；按登录令牌识别账号 |
| `backend/app/accounts.py` | 账号、密码散列、登录会话、锁定、账号管理与初始账号 |
| `frontend/src` | React + TypeScript 页面：经营总览下钻与溯源面板、成本日报、基础信息填报、日报审核、规则确认、主数据维护、历史记录（计算批次）、角色与权限 |

## 费用导出

专业部室（和企划财务部）在「费用导出」页选择成本科目（可多选，选上级即含全部下级）和起止期间，页面预览后导出 Excel：

- 工作表：按时间、按市场、按区块、按队伍，每个维度一张，行是成本科目（含上级小计），列是该维度的各个对象，另有“涉及井数”和合计；可再附“事项明细”工作表（逐笔事项，便于 Excel 透视）。
- 口径：经济事项有效金额合计（冲销已抵消），单位元；市场、区块取单井基础信息；队伍取事项发生时的施工队伍，事项上没有队伍的按该井当期施工队伍补，仍没有的记“未归属”。
- 权限：部室只看到归口给本部室的科目、看不到收入；基层队不可用。每次导出记入审计日志（对象类型“导出”）。
- 接口：`GET /api/cost-detail/options`、`GET /api/cost-detail?by=period|market|block|team&items=&start=&end=`（预览）、`GET /api/cost-detail/export.xlsx?by=period,market,block,team&detail=true`（导出）。

## 单井基础信息

基层钻井队在「基础信息」按井登记，字段按数据类型分为五段：基本信息（文本与选择）、井深（数值）、施工节点（日期时间，按设计开次逐行填开钻与完钻）、人员（整数）、自动计算（只读）。

- 自动计算口径与原表一致：钻前周期 = 一开 − 搬安，钻井周期 = 完钻 − 一开，完井周期 = 完井 − 完钻；登记滞后 = 填报时间 − 一开时间；完井时间填报超过 2 天记为滞后；状态按节点推导为 计划 / 正钻 / 完钻 / 完井。
- 阻断：必填项缺失、节点时间倒序、超出设计开次、缺前置节点（如有二开无一开完钻）、井号已由他队登记。警告：未来时间、登记滞后、完井填报滞后、完钻时间与末开次完钻不一致。
- 提交即汇总（管理层侧栏的“基础信息”页面已取消，汇总、导入导出、退回接口暂保留在后端），同时由节点推导施工时段，供成本日报表头和规则适用条件使用；有已审核事实的期间自动重算。
- 施工有新进展时点“更新基础信息”生成新版本，填报时间沿用首次提交，完井填报日期在首次填完井时间时记录。
- **退回队伍修改**：企划财务部在汇总表点开某井，填写原因后退回；队伍在填报页看到原因，修改后重新提交。重新提交前汇总表和主数据仍按当前已提交版本，页面上方列出所有待队伍修改的井。
- **按原表格式导入**：企划财务部上传《单井基础信息表》格式的 Excel（按表头名称取列），先预览逐行结果再确认。每行跑与线上填报相同的校验：通过的直接汇总（已登记的井生成新版本，内容相同的记为无变化，可重复导入）；有阻断项的生成草稿退回对应队伍修改；井号或队号为空、文件内重复、他队已登记的跳过。队号不存在时自动新建队伍；周期、状态、滞后由系统重算，填报时间和完井填报日期沿用原表。

## 成本日报

依据《核心数据库表设计》附录 A 的计价类型和 business_fact 事实类型，成本日报只收“需要基层采集、参与成本计算”的量，按事实类型分五段：

| 段 | 事实类型 | 填什么 | 计入哪些费用 |
| --- | --- | --- | --- |
| 一、进尺与工况 | 进尺、工况时间 | 起止井深（进尺自动算）；10 类工况小时，合计 24 | 形象收入、渤钻泥浆服务、定向与提速（按米）；工况用于校验和规则条件 |
| 二、能耗与材料消耗 | 材料消耗 | 柴油、润滑油、网电用电量、用水 | 柴油、润滑油、电费、水费 |
| 三、设备与工具在用 | 设备台时（天） | 在用天数 + 设备编号 | 钻具租赁、井控、设备租赁 |
| 四、外包技术服务 | 外包服务 | 服务量 + 签证单号（必填） | 外部泥浆、钻头服务、定向、提速、钻井工具、固井、下套管、试压、录井、测井、欠平衡、井下作业 |
| 五、运输与环保 | 外包服务 | 台班、趟、方量 + 单据号（必填） | 运输、环保、泥浆不落地、冬防保温、架线 |

- **人员出勤不再逐日填报**：每天的人员出勤事实由系统按「基础信息」中的人员数量（合同化、市场化、第三方，取当天结束前最后提交的一版）自动生成——合同化 + 市场化 → 合同化·市场化职工（C1-01-01），第三方 → 第三方用工（C1-01-02）；直接人工费、伙食费、地区补贴按此核算。基础信息里没有人员数量时，日报提示警告。原“倒班人次”与“其他劳务”报量行随之取消。
- 共 55 个报量项目（主数据维护 → 日报报量项目），以末级费用项目编码为键，规则按同一编码取量；伙食费这类不指定项目的规则按全部在册人员计价。
- 每段默认只显示常用项目、本井有规则计价的项目和近 30 天报过的项目，其余从“＋ 添加项目”中选；新日报沿用上一张已审核日报的在用设备。
- 另外 60 个成本项目不由基层填报，填报页列出原因：系统按施工期自动生成（制造费、折旧、长摊、项目部、通讯）、由进尺或出勤计算、物资系统出库接口、财务摊销、比例计提、部室凭发票签证据实或人工计价。
- 校验：阻断（工况合计、井深、进尺与钻进、外包服务缺单据号、数量为负）；警告（服务与工况不符，如报了测井但无测井工况、出勤为 0、用量偏离历史、进尺超范围、补报超时）；提示（暂无已发布规则的量，由归口部室补规则）。
- 旧版日报的行名（柴油、网电、定向服务）自动对应到现行编码，历史数据和金额不变；旧日报里逐日填的人员出勤行不再读取。

## 对标分析

经营总览 → 对标分析：

- **对比对象**：市场、区块、队伍各有一个多选框，选定具体对象（如 70101 与 70103 两支队伍、A区块与 B区块）只对比这些；不选表示全部。选项按其他维度已选条件联动收窄（选了 B区块，队伍只列 B区块施工的队伍），并显示井数。选了两个及以上对象的维度会自动加入分组。
- **分组方式**：市场、区块、队伍可任意组合，例如只选西北市场、按队伍分组，就是西北市场内各队对标。
- **对标基准**：全部井合计、所选范围合计，或指定其中一个分组作为标杆。
- 每组汇总形象收入、成本、毛益、净利润，计算毛益率、利润率、单井（井·月）平均、单位进尺成本（只用有进尺事实的井·月）。与基准的差：比率以百分点、金额以百分比显示，按“越高越好 / 越低越好”标好坏。排名图按所选指标排序，竖线为基准；分组可展开到单井并下钻。

## 单井经营结果模板导入

经营总览 → 模板导入（企划财务部）：上传《单井经营情况导出模板》格式的 Excel，一个工作表一口井一个月，可先“下载模板”。先预览后确认。

- 按末级项目导入为“历史导入”经济事项，形象收入导入为收入事项；汇总行由系统重算，与明细不一致时提示。
- 已导入的科目，规则不再重复计算；导入后该井该月重算一次，未导入的科目仍按规则计算（如计提为 0 时按比例规则计提，预览会提示）。
- 同一井同一月再次导入：金额相同记为无变化，不同则冲销旧记录后重新导入。该井该月已有规则计算的事项时不允许导入，历史数据只能补系统上线前的期间。
- 新井按表头建档、按队号挂当月施工时段（队伍不存在则新建）；已有井以系统中的单井信息为准，表头不一致只提示。
- 本期含历史导入金额的井，在经营总览和单井页备注“历史数据导入”，单井页列出导入来源文件。

## 金额口径

- 金额（元）一律保留整数：规则引擎每笔经济事项按四舍五入（0.5 进位）取整到元后入库，模板导入、历史导入和示例数据同样取整；毛益、净利润和各级汇总都是整数相加，层层对得上。
- 页面、溯源公式和导出的 Excel（千分位整数格式）里的金额都显示整数。单价、数量、计提比例不取整（如 0.68 元/千瓦时、2.00%）；万元口径的汇总指标仍显示两位小数，由整数元换算而来。
- 旧库升级：已有的规则计算事项在下次重算时按新口径冲销并重新生成，历史导入的小数金额显示时取整；要完全统一，删除 `backend/data/tfos.db` 重建即可。
